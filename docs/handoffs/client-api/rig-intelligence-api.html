1Overview & how it works

What the API gives you and the one idea that governs all of it.

The RIG Intelligence API is a read API over your provisioned intelligence scope. Every request returns coverage and analytics drawn from three underlying content pillars — news articles, newspaper cuttings, and YouTube — enriched with directed sentiment, entity resolution, grouped stories, district geography, and daily briefings. You can also manage your own scope (the entities, keywords, regions and mutes you track) programmatically.

One idea to remember: your key is your scope. Every endpoint is automatically filtered to what your organisation is provisioned for. Nothing you pass in a request can widen that — an out-of-scope entity, article, or district returns the same 404 as one that doesn't exist. This is what lets you share the API across your team without any request accidentally reaching another tenant's data.

Content vs. analytics

Everything the API exposes is either content (a specific article / cutting / clip) or an aggregate computed over that content (sentiment, topic counts, coverage volume, stories, geo). Every aggregate is drillable — it returns the IDs of the items behind the number, which you can fetch individually.

Base URL

https://api.rig360media.com/v1

A same-origin alias is also available at https://desk.rig360media.com/osint/v1 for browser-based tools that need to avoid CORS. Both route to the identical API.

2Authentication & your key

Bearer-token auth. Your key encodes your organisation and your limits.

Every request must carry your API key in the Authorization header:

curl https://api.rig360media.com/v1/entities \
  -H "Authorization: Bearer rig_live_YOUR_KEY_HERE"

An X-API-Key: rig_live_… header is also accepted if a Bearer header is inconvenient in your stack.

Key prefixEnvironmentNotes
rig_live_…ProductionLive data, counts against your monthly quota.
rig_test_…SandboxSame API surface for integration testing.
Your key is delivered separately. For security, the secret is never included in this document — it is sent to you once, over a secure channel. We store only a one-way hash of it, so it cannot be re-displayed; if it is ever lost or exposed, we revoke and reissue. Treat it like a password: never commit it to source control or paste it into shared tools.

Your key is a management key. Your organisation's key carries the can_manage capability, which means you can configure your own scope through the API (see §5) — add or remove any entity or keyword yourself, on demand, without waiting on us.

Failed authentication

A missing, malformed, revoked, or expired key returns an identical terse 401 — the API never reveals which of those it was, so a leaked key can't be probed for its state.

{ "error": { "code": "unauthorized", "message": "Invalid or missing API key", "status": 401 } }

3Conventions

Read once; these hold across every endpoint.

Response envelope

Every successful response is wrapped in a data field; list endpoints add a meta block with counts and paging.

{
  "data": { ... },              // the payload — object or array
  "meta": { "count": 20, "next_cursor": "eyJ0Ijoi…" }   // on list endpoints
}

Every error uses the same shape:

{ "error": { "code": "bad_request", "message": "human-readable reason", "status": 400 } }

Status codes

CodeMeaning
200Success.
400Malformed request (bad date, bad body). Message explains what.
401Missing / invalid key.
404Not found or out of your scope — deliberately indistinguishable.
422A query parameter failed validation (wrong enum / type).
429Rate limit exceeded — see the X-RateLimit-* headers.

Pagination

List endpoints are cursor-paged. When more results exist, meta.next_cursor is non-null; pass it back as ?cursor= for the next page. The newspapers feed uses a timestamp cursor ?before= returned as meta.next_before. A null cursor means the last page.

Time windows & limits

ParameterDefaultBounds
window (days back)71–90
limit (page size)201–100 (larger asks are clamped, not rejected)

Rate limits & quota

Each response carries X-RateLimit-Limit, X-RateLimit-Remaining, and X-RateLimit-Reset (per-minute window). Monthly consumption is tracked against your quota and is readable any time at GET /v1/usage.

The article object (also used for story timelines, entity coverage, and district drill-downs):

FieldMeaning

Source flags are provenance, not a verdict. political_lean is only present when an outlet is classified (left … right); low_credibility marks outlets on a curated low-credibility/state-propaganda list. Absence is not an endorsement, and neither flag is a claim about a specific article's truth.

Newspaper (cutting) fields

id, headline/headline_original, subheadline, full_text/full_text_original, source, section, language, geo, page_number, edition_date.

YouTube (clip) fields

id, video_id, title, channel, url, published_at, language, transcript_source, segment_count, and the assembled transcript. See §9 for the on-demand access rule.

5Managing your scope

Your key can configure its own coverage — add any entity or keyword, any time.

Your scope is the set of things the API filters everything to: provisioned entities, free-text keywords, topics, regions, mute_terms, and per-keyword priorities. Because your key carries can_manage, you control all of it programmatically — you never need to wait on us to add an entity or keyword.

GET/v1/scope
Read your current provisioned scope.
Example response
{
  "data": {
    "all_entities": false,
    "entity_ids": ["d2da8f86-…-b1ecf5a8d62d", "9a70e644-…-1a9e68aae1ed"],
    "topics": [], "keywords": ["irrigation project", "kaleshwaram"],
    "regions": ["Telangana"], "languages": [], "mute_terms": ["horoscope"],
    "keyword_priorities": { "kaleshwaram": 5 },
    "can_manage": true
  }
}
PATCH/v1/scopemanagement key
Add or remove items from your scope. All fields optional; send only what you're changing.
Body fields
FieldEffect
add_entitiesAdd entities — by name or by id. A name is resolved to a known entity; if it matches none, it's added as a keyword instead (never dropped).
remove_entitiesRemove entity ids from scope.
add_keywords / remove_keywordsArbitrary free-text terms — no dictionary needed.
add_topics / remove_topicsTopic filters.
add_regions / remove_regionsRegion names (e.g. Telangana).
add_mute_terms / remove_mute_termsTerms to suppress from your feeds.
keyword_prioritiesMap of keyword → integer weight (merged in).
languagesReplaces the language allow-list.
Example request
curl -X PATCH https://api.rig360media.com/v1/scope \
  -H "Authorization: Bearer rig_live_…" -H "Content-Type: application/json" \
  -d '{ "add_entities": ["K. T. Rama Rao", "Some New Local Leader"],
        "add_keywords": ["kaleshwaram"], "add_regions": ["Telangana"] }'
Example response — names resolved, unknowns kept as keywords
{
  "data": {
    "all_entities": false,
    "entity_ids": ["…", "d2da8f86-…-b1ecf5a8d62d"],
    "keywords": ["kaleshwaram", "some new local leader"],
    "regions": ["Telangana"],
    "resolved_entities": [ { "name": "K. T. Rama Rao", "entity_id": "d2da8f86-…-b1ecf5a8d62d" } ],
    "added_as_keywords": ["Some New Local Leader"]
  }
}
Nothing you ask to track is ever silently dropped. Give add_entities a name we recognise and it becomes a resolved entity (best, indexed matching); give it something we don't recognise and it's added as a free-text keyword. The response tells you exactly which happened via resolved_entities and added_as_keywords.
POST/v1/scope/purgemanagement key
Clear your scope and webhook subscriptions. Requires an explicit confirmation flag in the body.

9YouTube transcripts

Keyword-driven and on-demand: discover a clip via a query, then read its full transcript.

YouTube is on-demand, not a browsable feed. There is deliberately no "list all clips" endpoint. You first surface clips with a keyword or entity query (/analytics/keyword-sentiment?pillars=clips, /analytics/sentiment?include_youtube=true, or an entity's coverage?pillar=clips). Those return clip_ids. You may then fetch the full transcript of any clip you surfaced, within a rolling 24-hour window. A clip you never surfaced — or one surfaced by another organisation — returns 404.

Step 1 — surface clips with a query

curl "https://api.rig360media.com/v1/analytics/keyword-sentiment?keyword=Revanth+Reddy&pillars=clips&window=45" \
  -H "Authorization: Bearer rig_live_…"

→ { "data": { "keyword": "revanth reddy", "n_matched": 80, "n_scored": 62,
              "stance": { "positive": 11, "negative": 30, "neutral": 21 },
              "stance_score": -0.306,
              "clip_ids": ["9693", "9673", …], "pillars": "clips", "partial": true } }

Step 2 — fetch the full transcript

GET/v1/clips/{clip_id}on-demand · 24h window
The full transcript of a clip you surfaced, assembled from its timed segments.
{
  "data": {
    "type": "clip", "id": "9693", "video_id": "oLpqNGFPMZA",
    "title": "Ghantaravam 9 AM | Full Bulletin | 9th July 2026 @etvtelangana",
    "channel": "ETV Telangana",
    "url": "https://www.youtube.com/watch?v=oLpqNGFPMZA",
    "published_at": "2026-07-09T04:18:32+00:00",

13Analytics & sentiment

Directed sentiment, per-outlet lean, topic mix, coverage volume, and arbitrary-keyword sentiment.

Directed sentiment

GET/v1/analytics/sentiment
Two-field sentiment toward an entity (by id or name), split by pillar, with a daily trend. Add ?include_youtube=true to append an on-demand YouTube pillar.
Example — sentiment toward K. T. Rama Rao
{
  "data": {
    "subject": "K. T. Rama Rao", "window_days": 7,
    "total": 151,
    "split": { "supportive": 28, "neutral": 73, "critical": 50 },
    "net_lean": -0.1457,
    "impact": { "positive": 23, "negative": 26, "neutral": 23, "not_relevant": 79 },
    "by_pillar": {
      "articles":  { "total": 148, "split": {"supportive":28,"neutral":71,"critical":49}, "net_lean": -0.1419 },
      "newspaper": { "total": 3,   "split": {"supportive":0,"neutral":2,"critical":1},   "net_lean": -0.3333 }
    },
    "daily": [ { "date": "2026-07-02", "supportive": 1, "neutral": 11, "critical": 12 }, … ]
  }
}
Two fields, not one. stance (surfaced as the supportive/neutral/critical split) is the tone of coverage; impact is whether events are good or bad for the subject by consequence. net_lean = (supportive − critical) ÷ total. Figures are a classified, entity-linked sample.

Per-outlet lean

GET/v1/analytics/outlets
Which outlets cover an entity most, and their net lean toward it. ?entity= (id), ?window=, ?limit=.
{ "data": { "subject": "K. T. Rama Rao", "window_days": 7,
  "outlets": [ { "name": "Namasthe Telangana", "count": 72, "net_lean": 0.0517 },
               { "name": "Mana Telangana",     "count": 20, "net_lean": -0.3333 } ] } }

Keyword sentiment (arbitrary term, on-demand)

GET/v1/analytics/keyword-sentiment
Live two-field sentiment for any word or phrase — it need not be a provisioned entity. ?keyword=, ?pillars=articles|clips|both, ?scope=true to constrain to your entities/region, ?window=. Returns article_ids / clip_ids for drill-down.
Because results are live-scored, the first call for a term takes a few seconds; identical article-only queries are cached. partial: true means scoring hit its time budget and returned the newest matches.

14Webhooks

Push alerts to your endpoint when new coverage matches a filter.

POST/v1/webhooks
Subscribe an https:// endpoint to events, optionally filtered by entity / topic / sentiment. The signing secret is returned once, here only.
Request & response
POST /v1/webhooks
{ "url": "https://your-host.gov.in/rig-hook",
  "events": ["new_coverage", "critical_sentiment"],
  "filter": { "entity": "d2da8f86-…" } }

→ { "data": {
      "id": "5515379e-…", "url": "https://your-host.gov.in/rig-hook",
      "filter": { "entity": "d2da8f86-…", "sentiment": "critical" },
      "events": ["new_coverage", "critical_sentiment"],
      "is_active": true,
      "secret": "whsec_5d001f05982f1ce8…3bb677aa" } }
Events
EventStatus
new_coverageDelivered — new matching item in your scope.
critical_sentimentDelivered — new critical-sentiment coverage (adds a sentiment=critical filter).
spike, high_priority_storyAccepted & stored; detectors rolling out (returned under events_pending).
Verifying delivery. Each POST to your endpoint is signed X-RIG-Signature: sha256=HMAC(secret, body). Recompute the HMAC over the raw body with your whsec_… secret and compare, to confirm authenticity.

List returns your subscriptions (without secrets). Delete is scoped to your org (up to 25 webhooks).

16Common workflows

End-to-end sequences that combine the endpoints above.

A. Provision your scope, then read your world

  1. PATCH /v1/scope with your entities (by name), keywords and region.
  2. GET /v1/brief/today for the grouped digest, or GET /v1/articles for the raw feed.
  3. GET /v1/stories for the multi-outlet stories in your scope.

B. Sentiment on an entity — and the coverage behind it

  1. GET /v1/analytics/sentiment?entity=<name-or-id> → the split + daily trend.
  2. GET /v1/articles?entity=<id>&sentiment=critical → the critical articles driving it.
  3. GET /v1/analytics/outlets?entity=<id> → which outlets are most negative.

C. Find YouTube coverage of a topic, then read a transcript

  1. GET /v1/analytics/keyword-sentiment?keyword=<term>&pillars=clips → clip_ids.
  2. GET /v1/clips/<clip_id> → the full transcript (within 24h of surfacing).

D. Real-time alerting

  1. POST /v1/webhooks with events:["critical_sentiment"] filtered to your key entities.
  2. Verify each delivery's X-RIG-Signature, then act on the payload.
